# 操作系统笔记：虚拟内存、页表、TLB、ASID 与上下文切换

> 本章核心问题：
>
> **程序看到的地址和真实内存地址为什么不同？操作系统如何管理内存？进程切换时 CPU、页表、TLB 如何协作？**

# 1. 为什么需要虚拟内存（Virtual Memory）

## 1.1 直接使用物理内存的问题

早期系统中：

程序直接访问物理地址：

```
程序地址
    |
    v
物理内存(RAM)
```

存在问题：

### ① 进程无法隔离

例如：

进程 A：

```
地址1000
```

进程 B：

```
地址1000
```

如果直接对应物理地址：

```
A修改1000

↓

B的数据被破坏
```

因此不同进程必须拥有独立地址空间。

---

### ② 内存碎片问题

假设连续分配：

```
RAM:

[A][空][B][空][C]
```

虽然总空闲空间足够，但是不连续。

例如：

需要20MB连续空间：

```
空闲:

10MB + 10MB
```

仍然无法分配。

---

### ③ 程序不一定需要全部数据

例如：

游戏：

```
100GB
```

但是当前只需要：

```
地图1
```

没必要全部加载到RAM。

---

因此引入：

# 虚拟内存

核心思想：

> 给每个进程一个独立、连续、巨大的虚拟地址空间，实际由操作系统映射到有限的物理内存。

结构：

```
进程

虚拟地址空间

        |
        |
        v

    地址转换

        |
        v

物理内存(RAM)
```

# 3. 分页机制（Paging）

为了方便管理，操作系统把内存切成固定大小。

## 3.1 页(Page)

虚拟内存：

```
Page0
Page1
Page2
...
```

通常：

```
4KB
```

---

## 3.2 页框(Frame)

物理内存：

```
Frame0
Frame1
Frame2
...
```

大小同样：

```
4KB
```

---

映射：

```
虚拟页(Page)

        ↓

物理页框(Frame)
```

例如：

```
Page0  ---> Frame10

Page1  ---> Frame50

Page2  ---> Frame3
```

---

# 4. 地址拆分

虚拟地址：

```
+----------------+-------------+
|  页号 VPN       | 页内偏移     |
+----------------+-------------+
```

例如：

页面大小：

```
4KB = 2^12 byte
```

因此：

页内偏移：

```
12 bit
```

剩余：

虚拟页号。

---

为什么偏移不用转换？

因为：

页大小相同。

例如：

虚拟地址：

```
Page5 + offset100
```

页表：

```
Page5 -> Frame20
```

得到：

```
Frame20 + offset100
```

# 5. 页表(Page Table)

## 5.1 作用

页表记录：

```
虚拟页
   |
   v
物理页框
```

例如：

|虚拟页|物理帧|
|---|---|
|0|5|
|1|20|
|2|100|

---

每个进程拥有自己的页表。

原因：

不同进程：

```
相同虚拟地址

↓

不同物理地址
```

例如：

进程A：

```
Page10 -> Frame100
```

进程B：

```
Page10 -> Frame500
```

```

```

# 7. 状态位

---

## 7.1 Present 位

表示：

页面是否在RAM。

例如：

```
Present=1
```

表示：

```
页表映射有效
```

---

如果：

```
Present=0
```

表示：

```
页面不在内存
```

可能：

在磁盘。

---

## 7.2 Dirty 位（修改位）

表示：

RAM中的页面是否被修改。

例：

磁盘：

```
x=10
```

加载：

```
RAM:

x=10
```

程序修改：

```
RAM:

x=20
```

此时：

```
RAM != Disk
```

所以：

```
Dirty=1
```

---

作用：

决定换出页面时：

是否写回磁盘。

### Dirty=0

```
RAM:

x=10

Disk:

x=10
```

一样。

直接丢弃。

---

### Dirty=1

```
RAM:

x=20


Disk:

x=10
```

不同。

必须：

```
RAM

↓

Disk
```

写回。

---

## 7.3 Accessed 位

记录页面是否最近访问。

用途：

页面置换算法。

例如：

LRU、Clock。

---

## 7.4 Global 位

标记共享页面。

例如：

内核代码：

所有进程共享。

切换进程时：

不用删除相关TLB。

# 9. TLB（Translation Lookaside Buffer）

## 9.1 为什么需要TLB？

如果每次访问：

先查页表：

```
访问页表

↓

访问数据
```

一次内存访问变两次。

因此加入缓存：

TLB。

---

TLB：

本质：

> 页表项缓存。

保存：

```
虚拟页 -> 物理帧
```

---

## 9.2 TLB命中

例如：

TLB：

```
Page5 -> Frame20
```

访问：

```
Page5
```

直接：

```
Frame20
```

不用查页表。

---

## 9.3 TLB缺失

没有找到：

流程：

```
访问TLB

↓

查页表

↓

得到物理帧

↓

更新TLB
```

---

# 10. ASID（地址空间标识符）

## 10.1 没有ASID的问题

TLB：

```
VPN -> PFN
```

进程A：

```
1000 -> 5000
```

进程B：

```
1000 -> 9000
```

虚拟地址一样。

切换进程后：

TLB不知道是谁的。

所以：

必须：

```
刷新TLB
```

---

# 11. ASID解决方案

TLB增加字段：

```
ASID + VPN -> PFN
```

例如：

|ASID|VPN|PFN|
|---|---|---|
|1|1000|5000|
|2|1000|9000|

---

现在：

TLB知道：

```
这个地址属于哪个进程
```

---

# 12. 为什么切换进程需要修改当前ASID？

关键：

TLB里面保存：

```
历史进程的ASID
```

CPU内部保存：

```
当前运行进程的ASID
```

---

例如：

TLB：

|ASID|VPN|PFN|
|---|---|---|
|1|1000|5000|
|2|1000|9000|

当前：

```
Current ASID=1
```

访问：

```
VPN=1000
```

查：

```
(1,1000)
```

得到：

```
5000
```

---

切换到B：

修改：

```
Current ASID=2
```

TLB不用动。

访问：

```
VPN=1000
```

查：

```
(2,1000)
```

得到：

```
9000
```

---

核心：

> TLB里的ASID是标签，CPU当前ASID是查询条件。

# 2. 外设为什么需要访问 RAM？

假设：

你运行游戏。

CPU：

```
执行游戏代码
```

GPU：

```
渲染画面
```

GPU 需要：

```

```

```

顶点数据

```

都在 RAM。

GPU 需要拿。

## 最简单的方法

让 CPU 搬。

```
地址1000:
00101010
```

执行：

```

```

```
RAM
 |

 |

```

GPU 每秒需要传：

```

```

CPU 大部分时间：

搬数据
搬数据
搬数据
```

```

---

# 3. DMA 的核心思想

一句话：

> 让专门硬件负责搬数据，CPU 只负责下命令。

以前：

```
CPU:
    RAM读
    |
    写GPU
```

现在：

```
CPU
 |
告诉DMA:

"把RAM地址1000-2000的数据
复制给GPU"

DMA:
 |
自己搬
 |
RAM <------> GPU
```

CPU 可以继续运行。

---

类似：

搬家。

没有 DMA：

```
老板(CPU)
自己搬所有箱子
```

DMA：

```
老板:
"把这些箱子搬过去"

搬家公司(DMA):
自己完成
```

# 4. DMA Controller 是什么？

DMA Controller：

本质：

> 一个专门负责数据搬运的小处理器

它拥有：

- 地址寄存器
- 计数器
- 控制逻辑

例如：

CPU 设置：

```
source = 0x1000

destination = GPU buffer

size = 1GB
```

然后：

DMA：

```
while(size):

    read RAM

    write GPU
```

---

CPU 不参与每一个 byte 的移动。

# 5. 早期 DMA：集中式 DMA

视频讲：

## Centralized DMA

也叫：

Third Party DMA

为什么叫第三方？

因为：

CPU 第一方

外设第二方

DMA 控制器第三方

结构：

```
             Bus

CPU --------|
            |
RAM --------|------ DMA Controller
            |
GPU --------|
```

所有设备：

先找 DMA Controller：

GPU:

```
我要传数据
```

DMA:

```
好的
```

然后：

DMA 请求：

```
我要控制总线
```

Bus Arbiter：

```
批准
```

然后 DMA 开始搬。

---

## 为什么需要 Bus Arbiter？

因为总线同一时间只能一个人用。

例如：

CPU：

```
我要访问RAM
```

GPU:

```
我要访问RAM
```

同时：

线路冲突。

叫：

> Bus contention（总线竞争）

所以需要裁判：

Bus Arbiter

决定：

```
谁先用
```

# 7. 三种 DMA 工作模式

视频讲三个。

---

# 7.1 Burst Mode（突发模式）

一次拿走总线。

例如：

GPU：

复制：

```
1GB
```

DMA:

```
我要整个bus
```

然后：

```
DMA ---------------- RAM

疯狂传输
```

优点：

快。

缺点：

CPU 等。

类似：

搬家公司占电梯：

```
一次搬100箱

别人不能用
```

---

# 7.2 Cycle Stealing（周期窃取）

DMA：

不长期占用。

比如：

传：

```
一个cache line
```

释放。

再抢。

过程：

```
CPU
CPU
DMA
CPU
CPU
DMA
```

优点：

CPU还能运行。

缺点：

稍慢。

---

# 7.3 Transparent Mode（透明模式）

最礼貌。

DMA：

只在 CPU 不用 bus 时工作。

例如：

CPU：

```
休息
```

DMA：

```
偷偷搬一点
```

优点：

CPU完全不影响。

缺点：

速度慢。

# 8. DMA 和 CPU Cache 的关系（重要）

这里和你之前学的 cache 有联系。

问题：

DMA 占用 RAM 总线。

CPU 会不会停？

答案：

不一定。

因为：

CPU 有 cache。

例如：

CPU执行：

```

```

a,b:

已经在 L1 cache。

那么：

不需要访问 RAM。

所以：

DMA:

```
占RAM
```

CPU：

```
继续跑
```

---

但是：

如果 cache miss：

CPU：

```
我要RAM数据
```

发现：

DMA正在使用总线。

那么：

CPU stall。

等待：

```
DMA结束
```

# 10. 最关键：DMA 和虚拟内存

这是视频最后，也是 OS 最重要部分。

问题：

DMA 访问什么地址？

CPU 有：

虚拟地址。

例如：

程序看到：

```
0x400000
```

实际：

```
物理RAM:

0x12345000
```

靠：

页表。

---

那么设备呢？

GPU 也需要访问内存。

如果 GPU 直接使用物理地址：

危险。

# 15. 期末可能考什么？

## 问题1

为什么需要 DMA？

答案：

因为 CPU 如果负责所有外设数据搬运，会大量消耗 CPU 时间，降低系统吞吐量。DMA 允许外设直接访问内存。

---

## 问题2

DMA 是否完全不需要 CPU？

错误。

正确：

CPU负责：

- 初始化 DMA
- 设置地址
- 设置长度
- 启动 DMA
- 接收完成中断

DMA负责：

- 实际数据搬运

---

## 问题3

DMA 和虚拟内存有什么关系？

答案：

设备 DMA 使用 IOMMU，通过 IO 页表把设备虚拟地址转换为物理地址，同时提供隔离和保护。

---

## 问题4

为什么 DMA 会导致 CPU stall？

因为：

DMA 和 CPU 都需要访问内存总线。

当 DMA 占用总线时：

CPU cache miss 后需要访问 RAM，会等待。

---

# 总结一句话

这个视频讲的核心就是：

> **DMA 是让外设拥有“像 CPU 一样访问内存的能力”的机制；现代 PCIe 设备内部集成 DMA Controller，并通过 IOMMU 使用类似虚拟内存的机制安全访问 RAM。**

它正好连接你最近学的：

- 虚拟内存
- 页表
- MMU
- 中断
- 设备管理

如果继续学 JYY OS / 南大 OS，这部分通常会接在 **文件系统之前的设备与 I/O 系统**，属于非常核心的一块。你之前学的 CR3/TLB/ASID，其实可以自然扩展到这里的 IOMMU。

这个视频讲的是 **Memory-Mapped I/O（内存映射 I/O，MMIO）和 Port-Mapped I/O（端口映射 I/O，PMIO）**。

它和你刚刚看的 DMA 视频是连续关系：

- DMA 解决的是：

    > **设备如何高效搬运数据到 RAM**

- MMIO/PMIO 解决的是：

    > **CPU 如何和设备通信、控制设备**


也就是说：

```
CPU
 |
 | ① 命令设备（MMIO/PMIO）
 |
设备
 |
 | ② 搬数据（DMA）
 |
RAM
```

# 13. 期末重点总结

## Q1：什么是 MMIO？

答案：

> 将设备寄存器映射到统一物理地址空间，使 CPU 可以通过普通 load/store 指令访问设备。

---

## Q2：MMIO 为什么比 PMIO 好？

因为：

- 使用统一地址空间
- 不需要特殊 IO 指令
- 可以利用 CPU/cache/burst 优化
- 硬件设计简单

---

## Q3：用户程序为什么不能直接访问 MMIO？

因为：

- 安全
- 防止破坏硬件状态

必须：

```
system call
+
driver
```

---

## Q4：DMA 和 MMIO 区别？

||作用|
|---|---|
|MMIO|CPU控制设备|
|DMA|设备搬数据|

一句话：

> MMIO负责“告诉设备干什么”，DMA负责“设备自己搬数据”。

---

这两个视频合起来其实就是操作系统 **I/O 系统核心框架**：

```
             Application
                  |
             System Call
                  |
              Kernel
                  |
          Device Driver
                  |
        -----------------
        |               |
       MMIO            DMA
        |               |
     控制寄存器       数据搬运
        |               |
        ------ Device ------
                  |
                 RAM
```

这部分在 JYY OS / 南大 OS 里面通常属于 **设备驱动 + I/O subsystem**，也是理解 Linux 驱动、网卡、NVMe、GPU 工作原理的基础。你前面学的虚拟内存、页表、IOMMU 到这里刚好串起来。
